\subsection{Automated tests}
\label{sec:tests}

Phase 2 kept Phase 1's way of working: every change went through a pull request, and the CI run checks formatting, runs the linter with warnings as errors, and runs the full test suite on Ubuntu. On the final Phase 2 build the full suite passes \tbd{} tests on Ubuntu, \tbd{} of them added in Phase 2. The new parts that have no network or clock of their own are also tested alone, by unit tests: the directory, the claims, the gossip rules, and the outboxes and held updates. Table~\ref{tab:testfiles} lists the multi-node tests that Phase 2 added, by area. Most start real nodes on one machine and talk to them over real sockets; the rest use stand-in nodes, to check the client side alone.

Phase 1's two rules still held. Tests never sleep for a fixed time: they wait for a condition with a deadline. A test that touches timing must pass 10 times in a row before it merges. Phase 2 added a third habit. For many rules, the test itself was checked by breaking the rule on purpose, and the test had to fail. Examples are resending an offline report under a new ID, keeping offline claims only in memory, and dropping a gossip copy instead of holding it.
