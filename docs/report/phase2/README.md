# Phase 2 report (LaTeX)

The Phase 2 report, in its own folder so the submitted Phase 1 report one level up stays as it was. Why it is laid
out this way: D450 in [../../design-log.md](../../design-log.md). The style rule is Phase 1's (D266): a stand-alone,
third-person report that names no source files, functions, commits or design-log IDs in its text (comments are fine),
cites the repository once, and cites no course material.

```text
main.tex            preamble (copied from ../main.tex, lines 5 to 132), title page, abstract, references
sections/*.tex      one file per section, in the order main.tex lists them
figures/            not there yet: the Phase 2 charts go here, drawn from the analysis
```

Every other figure is drawn in TikZ or pgfplots inside the section files, with the preamble's styles (`nodebox`,
`clientbox`, `state`, `\seqactor`, ...), so it can be edited as text.

A skeleton has its `\section`, its `\label`, subsection headings drawn from the plan and the owner's design-log
entries, and one `% TODO(<name>)` block that lists what to cover and which entries and events to draw on. Keep the
`\label` of your section: other sections point to it.

## Markers

| Marker | Means | Who clears it |
|---|---|---|
| `% TODO(<name>)` | work for that person, here | the person named |
| `% TODO` | work for the assembler | Noor |
| `% CONFIRM` or `% CONFIRM(<name>)` | drafted from the repository's docs or history; check it is true | the person named, or the team |
| `% DRAFT` | text drafted by the agent, to be read and reworded | the section's writer |
| `% FILL` | numbers to type from `docs/phase2-results.md`; names the metrics | Noor, with each owner |
| `\tbd{}` | prints **[TBD]** in the PDF where a number or a result is missing | Noor, with each owner |

To list what is left:

```bash
grep -rn '% TODO\|% CONFIRM\|% DRAFT\|% FILL' docs/report/phase2
grep -rn --include='*.tex' '\\tbd{' docs/report/phase2 | grep -v ':[0-9]*:\s*%'
```

Nothing of either list may be left when the report is submitted.

## On Overleaf

1. Zip this folder's contents, so `main.tex` is at the top of the zip:
   `cd docs/report/phase2 && zip -r ../phase2-report.zip . -x README.md`.
2. In Overleaf: **New Project, Upload Project**, and pick the zip.
3. **Menu, Compiler:** pdfLaTeX (the default) works. **Main document:** `main.tex`.
4. Press **Recompile**. The first compile takes a while, for TikZ and pgfplots.

No LaTeX compiler was installed where the skeleton was written, so its first build on Overleaf is also its first
check. It uses only the packages the Phase 1 report loads.

## Locally

```bash
cd docs/report/phase2
latexmk -pdf main.tex          # with TeX Live
tectonic -X compile main.tex   # or Tectonic, which fetches packages itself
```

## Where the numbers come from

Nothing here is measured anew. Results are typed from [../../phase2-results.md](../../phase2-results.md), which
holds the tables generated by `analysis/analyze.py` over the Phase 2 runs (`runs/ph2*/`, the cells in
`experiments/phase2.list`), the same way the Phase 1 report was typed from `docs/phase1-report.md`. Phase 1 numbers
quoted for comparison come from the Phase 1 report. If a result changes there, change it here too.
